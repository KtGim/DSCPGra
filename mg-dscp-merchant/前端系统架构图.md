## 3. 路由与权限模型

```mermaid
sequenceDiagram
    participant U as 用户
    participant P as permission.js
    participant S as user store
    participant A as api/login.js

    U->>P: 访问任意路由
    alt 白名单路由
        P->>U: 放行(/login /signup /protocoldocx<br/>/questionnaire /registrationreturn<br/>/termApplicationForm 佣金模块)
    else 无 token
        P->>U: 跳 /login?redirect=
    else 有 token 且 URL 带 licence
        P->>S: 清除 token → 登录页
    else 有 token
        P->>S: getInfo() 校验
        S->>A: /merchant/profiles
        A-->>S: userInfo/menuList/menuTypeRole/excludeMenus
        alt 佣金用户(isCommisson)访问 dashboard
            P->>U: 强制跳 /referral-commission
        else 非佣金用户访问佣金路由
            P->>U: 弹回 dashboard
        end
    end
```

**菜单权限**:非动态路由,静态路由 + 前端按 `menuList`/`menuTypeRole`/`excludeMenus` 递归裁剪菜单(Administrator 全量 / Employee 白名单过滤)。

## 4. 请求链路(utils/request.js 核心资产)

```mermaid
sequenceDiagram
    participant V as 页面
    participant A as api 模块
    participant R as request.js
    participant B as 后端

    V->>A: 调用接口
    A->>R: request(config)
    R->>R: ① token 注入 header[Token]<br/>(isToken:false 跳过)
    R->>R: ② 竞态保护(GET默认)<br/>AbortController 取消同URL旧请求
    R->>R: ③ 请求去重(默认)<br/>in-flight Promise 共享
    alt repeatSubmit:true
        R->>R: ④ sessionStorage 1.5s 防重复提交
    end
    R->>B: 请求
    B-->>R: 响应
    alt code=401
        R->>V: ElMessageBox 重新登录(redirect)
    else code=500/601
        R->>V: Vuestic useToast 提示
    else HTTP 错误
        R->>V: Network Error/timeout/status 文案映射
    end
    R-->>V: 返回数据
```

**下载**:`download(url, params, filename)` — POST + form-urlencoded + blob 校验,非 blob 解析 JSON 报错,全屏 ElLoading。

## 9. 架构特点与风险

**特点**
- **双 UI 体系**:Element Plus(业务组件)+ Vuestic UI(布局框架/主题),Tailwind 辅助样式
- 请求层是全项目核心资产:竞态保护 + 去重 + 防重复提交 + 统一下载,质量高
- 菜单为"前端裁剪"而非动态路由,权限逻辑简单可控
- 9 种语言国际化,金额/日期/数字格式按语言切换
- 佣金提成为独立路由域(CommissionLayout),与主工作台隔离

**风险点**
1. **ExcelToPdfTool.vue 约 7786 行**、多个 index.vue 超千行,巨型组件亟需拆分(graphify 社区 cohesion 仅 0.03)
2. `user.isCommisson = false` 被硬编码,佣金闸门实际只走非佣金分支
3. `system/dict`、`validIndex.js` 等若依(RuoYi)遗留代码与新架构并存
4. OSS AK/SK 明文在 `.env`,前端直传无 STS 签名
5. 存在 2 处 3 文件循环依赖
6. 图谱基于 commit `95d4d398`,精确结论以当前源码为准
